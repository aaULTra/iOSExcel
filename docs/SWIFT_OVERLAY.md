# AppKit Swift overlay boundary

Actual loader 39023211961 (90de734c9ed10ca9075dd5581e8ad9fa78b3d43e)
passes ServiceManagement and stops before Microsoft entry at
/usr/lib/swift/libswiftAppKit.dylib, referenced by FluentUI. The same overlay is
loaded by CocoaUI, mso40ui and mso99. All 55 Microsoft and eight owned images map;
exit 134, no timeout, no Excel initialization or activation.

The exact three imported names are:

- _$s10Foundation9IndexPathV6AppKitE4itemSivg
- _$sSo6CGRectV6AppKitE4fill5usingySo22NSCompositingOperationV_tF
- __swift_FORCE_LOAD_$_swiftAppKit

Native capture 39023810431 used Apple Swift 6.1.2, MacOSX15.5 SDK and arm64 Mac
compiler probes. SIL references match both imported function names exactly:

- IndexPath.item getter: @convention(method) (@in_guaranteed IndexPath) -> Int.
- CGRect.fill(using:): @convention(method) (NSCompositingOperation, CGRect) -> ().

The measured native IndexPath size/stride/alignment is 17/24/8 bytes; CGRect is
32/32/8 and NSCompositingOperation is 8/8/8. Size alone does not prove cross-platform
representation or compatibility with the older Office compiler. A C function with
an ad-hoc symbol alias does not establish the required Swift calling convention.

Five valid two-component IndexPaths return their second component, including
Int.max. Invalid and non-two-component cases remain unmeasured. The exact Mac SDK
enum declaration yielded 29 compositing values (0 through 28, with their actual
names recorded); its raw type is NSUInteger/unsigned long. No drawing was executed.
The marker is weak in all four actual Office importing images. Swift 5.5 compiler
source emits a no-argument void link function and stores its address in a used
constant. The current Swift 6.1 compiler instead emits a common Boolean anchor.
The explicit current compiler probe captured that i1 false declaration. The marker
is generated by the compiler, rather than replaced with a hand-written API stub.
No native marker contents are read or called. This version difference does not
establish any application behavior.


Evidence: docs/evidence/swift-appkit-contracts.json and swift-appkit-values.json.
These contain metadata and own-probe results, not an Apple implementation.

Next implementation gates are compiler-generated matching Swift exports, actual
iOS type/ABI and cross-call validation, native drawing/state contracts for supported
compositing, and the force-load data contract. Unsupported drawing must fail
visibly. No overlay redirection or weakened load has been applied. A successful
capture is not a repaired loader, Excel startup, rendering or workbook milestone.

Reproduction is automated by .github/workflows/swift-appkit-contracts.yml using
original probes in tools; it does not download or execute Microsoft code.

## Typed prototype and current validation

The experiment in experiments/swift-appkit builds a module named AppKit, using
compiler-generated Swift function exports and a Clang-imported compositing enum
with the 29 captured native values. IndexPath.item handles two-component paths;
other lengths stop with a logged abort. CGRect.fill(using:) logs its typed argument
values then stops explicitly; drawing is not implemented. Aborting avoids relying
on Objective-C exception unwinding through Swift frames. The isolated prototype
has its own logger; production integration will require the common shim logger.

Native run 39030859803 (97c1d3ee8cddc7e851a95032544bf0dfcb207d57) passed all three
exact exports, verified the two callable symbols are code and the marker is data,
and matched five getter cases and all three measured layouts. Cross-ABI run
39030859773 stopped before Simulator execution because the test incorrectly
required a separate C AppKit load. The actual Mac fixture only directly imports the
Swift overlay; it imports both measured functions from that overlay. The setup now
permits this observed dependency shape. No Microsoft redirection has been applied.

The next gate runs original own-source Mac-compiled caller code retargeted to
Simulator alongside a native iOS caller, checking getter values, typed drawing
arguments before explicit failure, and invalid-path diagnostics. A device-target
compile/sign check is separate from runtime proof. Both drawing behavior and the
older Office compiler's actual calls remain unverified.

Primary compiler reference for the legacy marker:
https://github.com/swiftlang/swift/blob/swift-5.5-RELEASE/lib/IRGen/IRGenModule.cpp

## Cross-ABI checkpoint and drawing experiment

Run 39031123869 at 053ed90c5141c36f27aff514eab7b67a99a297da passed both the
native iOS caller and retargeted own Mac caller on M4 iOS 26.2 Simulator. Each
matched five IndexPath cases and all layouts, reached the typed rectangle argument
logger before expected missing-context abort, and rejected invalid paths. Device
platform-2 compilation/signing passed separately; no device execution occurred.
Evidence: swift-overlay-cross-abi.json and swift-overlay-device-build.json.

Native run 39031310785 at 9a3a9a41d3988960a758040101e7b33b63db8f9c captured 96
offscreen drawing cases: six finite rectangles, copy/sourceOver, flipped flags,
transforms and preexisting blend states. Full pixel bytes and follow-up fills expose
persistent graphics state. Evidence: swift-overlay-native-drawing.json.

The current experimental backend maps only copy/sourceOver into a current UIKit
CGContext, with save/restore. Mac testing uses an explicitly enabled thread-local
test context instead of an AppKit implementation. Exact pixels and follow-up state
must match all native cases before this subset is considered validated. Missing
context, nonfinite geometry and unmeasured operations log then abort. NSGraphicsContext,
other compositing, Microsoft compiler calls and real UI remain unimplemented or
unverified. No Microsoft load redirection has been applied.

## Validated pause checkpoint

Source 219af469e9ced14079ce81deb969e35f410857ad passed drawing run
[39038256936](https://github.com/aaULTra/iOSExcel/actions/runs/39038256936) and
cross-ABI run [39038256967](https://github.com/aaULTra/iOSExcel/actions/runs/39038256967).
All 96 full RGBA/state records matched native AppKit exactly on both the Mac test
context and UIKit current-context backend on M4 iOS 26.2 Simulator. The first
comparison had found all 16 negative-size cases differed: Quartz normalized and
painted the rectangle while native AppKit left it empty. The adapter now keeps
nonpositive dimensions empty; the other 80 cases needed no behavior change.

The same source passed native-iOS and retargeted own-Mac getter/layout tests,
typed drawing argument preservation before the expected missing-context abort,
and invalid-path rejection. Device platform-2 compilation/signing passed only;
no physical-device or Microsoft execution was performed. The old cross-ABI report
field `drawing_implemented: false` describes that no-context probe, not the separate
valid-context pixel test. The pixel report supplies the positive drawing evidence.

Evidence is preserved in docs/evidence/swift-overlay-drawing-validation.json,
swift-overlay-{native,macos,ios}-drawing.json.gz and
swift-overlay-checkpoint-{cross-abi,device-build}.json. Exact source, artifact IDs,
verified ZIP hashes and failed-attempt provenance are in
swift-checkpoint-provenance.json. Captured pixel bytes are generated probe data.
